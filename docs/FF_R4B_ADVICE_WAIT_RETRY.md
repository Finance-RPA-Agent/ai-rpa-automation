# R4B · 本地 AI 等待、规则回退与手动重试

**设置页的 Installed 只表示本地服务列出了指定模型。** 检查仍只读取 `/api/tags`。页面分别显示尚未检查、服务不可达、模型缺失和已安装。首次请求可能较慢，连接检查不执行推理，也不确认模型已驻留。

| 操作或状态 | 用户看到的结果 | 请求行为 |
|---|---|---|
| 打开任务、选择异常、渲染页面 | 显示获取解释的按钮 | 不发解释请求 |
| 明确点击解释或重试 | 立即显示等待，同一 finding 的重复点击被拦截。仍可离开页面或使用独立的人工复核控件 | 按当前任务、finding、revision 和 evidence 发送一次 POST |
| 等待满 10 秒 | 显示一次慢请求提示 | 计时器只更新显示 |
| 后端返回有效规则结果 | 标明规则来源和具体原因。此前已验证的规则事实在同一绑定的重试期间仍可用 | 超时、忙或不可用等结果由用户决定是否重试；不支持或证据不足时提示核对资料 |
| 页面等待满 60 秒 | 结束页面等待，提示本地模型可能仍在运行，要求刷新任务 | 中止前端等待，拦住旧任务快照的直接重试。迟到的响应不会重新显示 |
| 点击 Refresh task | 仅重新读取当前任务详情。失败时提示并保留拦截；成功显示新的任务详情后按最新证据重新判断准入 | GET 本身不请求解释。下一次 POST 需要用户再次点击 |

账户、任务、finding、revision、证据摘要、视图及选择切换会使旧请求的结果失效。已核验的规则建议只保存在当前页面内存；刷新后重新读取任务。错误响应不能产生规则事实，更不能产生审批、修正或回执。

新增 Python 专项使用合成账号、真实 ASGI 路由和 SQLite，分别控制 tags 探测、阻塞、超时、忙与成功响应。Node 专项运行实际三份前端脚本，通过假时钟和可控 HTTP 响应检查按钮、请求次数、迟到的 401、刷新失败与恢复。原版 G01、G02 的同断言失败记录与候选结果随本轮回传提供。

本轮保留原 AI 参数、建议预算与页面等待上限。实际冷启动耗时、后台推理取消、多窗口排队、原生界面、跨机和真人体验仍待相应验证。雨松负责技术统筹与采纳，ChatGPT 规划并独立审核，Codex 实现及整理本机证据。团队与 leng327 的既有贡献保持原归属。
