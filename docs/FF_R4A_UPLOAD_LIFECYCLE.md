# Finance Flow R4A · 失败上传的局部清理

旧版会先写入 `files/<file_id>/original.csv`，再解析和登记。未闭合引号的 CSV 会被拒绝，但原件仍留在磁盘，SQLite 中没有对应记录。

| 上传到达的位置 | 失败后的处理 |
| --- | --- |
| 角色、扩展名、大小检查或创建目录 | 保留原错误。只有独占创建目录成功，本请求才取得清理资格。 |
| 写原件、读表、校验，或尚未进入登记连接 | 核对本次目录身份与解析后的路径，仅 unlink 该原件，再用 rmdir 移除空目录。沿用原解析与业务错误。 |
| 登记事务抛错 | 确认写连接已关闭，再通过新连接按本次 ID 查询。没有记录才尝试清理。有记录则保留文件，继续抛出原登记错误。 |
| 关闭或查询失败 | 保留原件，以 HTTP 503 说明无法确认登记，并保留异常链。 |
| 登记成功后生成展示结果 | 展示处于清理范围之外。展示报错时，文件和登记均保留，可以用原 ID 重查。 |
| 路径已改向、文件占用、目录内还有其他文件等导致清理失败 | HTTP 503 明确提示无法确认清理。异常链保留原失败及清理原因。其他文件留在原处。 |

目录名由服务生成，上传显示名不参与清理。原 CSV/XLSX、source/reference、行列上限、原件校验和与后续字段映射继续使用原约定。文件夹被替换或被 junction 重定向时按可观察到的身份拒绝删除。检查与删除之间仍有操作系统竞态窗口，断电、进程强杀和同机恶意抢占路径不在本轮一致性保证内。
